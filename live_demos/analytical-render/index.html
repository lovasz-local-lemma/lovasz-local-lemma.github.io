From an integral to a boundary
  1. Integrate the cosine. For an unoccluded polygon emitter, diffuse irradiance reduces to its spherical boundary.
  2. Fit the glossy lobe. The garage reads published GGX LTC matrix/amplitude tables, transforms the polygon, and evaluates it deterministically.
  3. Account for visibility. Unoccluded emitters keep the two estimators comparable. A retained experimental polygon-clipping path covers only aligned rectangular blockers.

Why the scene changes

The CPU paths open a supported diffuse study, reduce resolution and disable GPU-only controls. The previous GPU scene and settings are kept for your return. The common scenes remain useful for comparing the same lighting integral.

Where the time goes

JS evaluates pixels in a main-thread loop. The compiled WASM kernel also runs on one CPU thread; it has no worker pool in this project. WebGPU dispatches many pixels concurrently. Resolution, light count and Monte Carlo samples multiply the work. WASM is not automatically faster than optimized JavaScript.

How much faster?

A recorded same-workload CPU audit measured 25.9 ms for JS and 4.5 ms for WASM: the moving trio at 192×100, split view, two MC samples. These are medians from this machine's Node/V8 run, excluding browser presentation—not a universal multiplier.

The live “Producer CPU time” includes actual CPU rendering for JS/WASM but only command submission for GPU. Dividing those numbers would not measure GPU speedup. The technical notes retain the complete measurements.
