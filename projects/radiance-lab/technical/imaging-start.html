Implementation notes describe the native application. A working experiment, an approximate preview and a general transport estimator establish different things; each document states its own scope.

Double-click Imaging-Lab.bat to open a separate depth-capture session in the paired studio. It uses the latest built executable and leaves the normal viewer's settings and any running viewer alone. The other tools are in the Render menu. The launcher also accepts -Tool Photo, -Tool Plate or -Tool Wave.

Depth acquisition

CW / four shots is absolute inside the declared capture range. CW / three frequencies uses coarse measurements to resolve wraps in a more precise fine measurement. Off-axis sensor or emitter ramps use two coarse four-shot anchors plus one fine fringe; the breakdown shows Fourier sideband selection and ambiguity resolution. Plane-front and line-emitter choices demonstrate their different path-to-range calibration.

Interactive refresh repeats acquisition after moving the camera. Sampling, sensor resolution and scene complexity determine refresh speed. Enabling multipath and medium is a useful apparent-range experiment; it does not guarantee recovery of the first visible surface. Acquisition, calibration and evidence.

High-quality photography

The selected renderer stays selected unless CPU VCM comparison is explicitly chosen. Resolution and samples/passes are independent quality controls. Long exposure averages linear light from camera positions before tone mapping. Time-lapse writes an image sequence along the same camera path. Both freeze scene simulation and animation; this version varies the camera, not simulation time.

Still PNGs preserve the finished viewport before selection outlines. Linear HDR/PFM exports omit display effects. Motion exposure is available for GPU tracing, VCM, UPBP, path guiding and photon primitives; other paths support still PNGs. CPU capture currently requires a sharp pinhole because its legacy camera paths do not implement the full lens model. Camera and export details.

Optical scope

The new camera uses an ideal thin-lens model with independent lens/sensor tilt and shift, aperture shape and rotation, and matched CPU/GPU primary rays. It does not simulate a multi-element commercial lens prescription. Legacy tilt remains available as a clearly labeled comparison.

The scene photograph is a depth-reprojected viewport overlay. It retains captured reflections, leaves disocclusion holes, and is not included in traced reflections or illumination. The separate wave laboratory performs genuine scalar coherent record/replay for a controlled layered scene. Arbitrary coherent capture and physically diffracting in-scene holograms remain further work. Photograph and wave-replay details.

Validation

Native runs exported GPU stills, a four-position exposure, a three-frame camera sequence, raster PNGs and CPU VCM images. Float images retained finite values above 1; dimensions and pass counts were checked. Numerical tests cover camera conjugacy, sampling and capture scheduling. Native OpenGL tests compare CPU/GPU rays and exercise depth recovery, rectangular phase resampling, RGB-D orientation/occlusion and hologram replay.
