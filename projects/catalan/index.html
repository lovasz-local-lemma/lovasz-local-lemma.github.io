Catalan structures

Different combinatorial objects share one recursive structure. Explore the bijections between trees, balanced parentheses, lattice paths and triangulations, then watch the reflection principle account for invalid paths. A focused combinatorics study with the correspondence made explicit.

The ideaBalanced parentheses, certain lattice paths, trees and polygon triangulations can encode the same recursive choices. A bijection translates each valid object into exactly one object of another kind, explaining why their counts agree.

What to watchFollow one object's choices through the different representations and see which paths the boundary excludes.

The idea behind it

The appeal here is how many disguises one counting problem can wear. I want the correspondence itself to be visible, so a tree, a path and a triangulation become different ways of thinking about the same recursive choice.

Working intuition Split an object at its first choice, and the same recurrence appears in several forms.

A building block for thinking about structure

The shared count is the beginning. The useful question is how the same recursive split appears in a tree, a balanced expression, a lattice path or a triangulation. This is a compact idea showcase rather than a large software system; it supplies structural intuition for the tree-based tools elsewhere in the portfolio.

One count, several concrete objects

Catalan numbers appear in objects that initially look unrelated: balanced parentheses, full binary trees, non-crossing circle matchings and polygon triangulations. This study builds the small cases explicitly and lets the viewer browse one configuration at a time, animate through the collection or display the whole set.

The application generates the structures recursively. Parenthesis generation enforces valid prefixes; tree generation combines possible left and right subtrees; matching and triangulation generators split their boundary into smaller subproblems. You can inspect the objects that contribute to each count.

Show why some paths are excluded

The lattice-path view separates valid paths from unrestricted monotone paths. Turning on invalid examples reveals the first crossing of the diagonal, and a reflection overlay exchanges the remaining horizontal and vertical steps. Their reflected endpoints land at the same off-diagonal destination, making the subtraction in the counting argument visible.

This view includes valid and invalid totals, individual path strings and a zoomable overview. It gives the closed-form count a geometric explanation that can be checked against every generated example at the selected size.

Connect the representations

Balanced parentheses also appear as up-and-down mountain paths, connecting a symbolic sequence to its geometric profile. A paired view places a non-crossing matching beside a polygon triangulation at the corresponding position in their recursive enumerations. The two drawings make the repeated splitting pattern easier to compare.

React manages the selected size, view and playback state; Canvas draws the structures, while the interface supplies mathematical notation and explanatory controls. For the selected size, every generated object can be inspected individually or in the complete collection.

Current scope

  • The interface deliberately limits n to 1–5. It enumerates complete collections in memory, so the approach is intended for small cases rather than large combinatorial generation.
  • The matching/triangulation view pairs generated examples; it does not provide arbitrary object conversion or animate a correspondence between individual chords and diagonals.
