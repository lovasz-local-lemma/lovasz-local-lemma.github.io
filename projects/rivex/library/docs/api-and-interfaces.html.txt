    <h1>RIV — API &amp; Interfaces</h1>
    <p class="lede">The official Rive runtime parses the file and runs the scene, then hands
      drawing to an <b>abstract render interface</b>. This project implements that entire
      interface from scratch — a second, independent renderer for the same <code>.riv</code>.
      Here is the exact contract, how we satisfied each piece, what we reuse unchanged, and
      the binary &amp; feather internals where ours meets the original.</p>
    <div class="badges">
      <span class="badge"><b>7</b> render interfaces implemented</span>
      <span class="badge"><b>2</b> conforming renderers · ours ∥ PLS</span>
      <span class="badge">parse · model · animation = <b>reused</b></span>
      <span class="badge">round-trips through <b>File::import</b></span>
    </div>
    <p class="crumbs">Companion to <a href="project-structure.html">RIV — Project Structure</a>.</p>
  </header>

  <section>
    <h2><span class="num">01</span>The contract — one interface, two implementations</h2>
    <p class="sub">Rive's runtime never draws pixels itself. It builds a scene of <em>Core</em>
      objects and emits draw commands against a set of pure-virtual interfaces. Anyone who
      implements those interfaces gets a working renderer. Rive ships one (the GPU "Rive
      Renderer", PLS). We wrote a second.</p>

    <div class="card">

              — the Pixel-Local-Storage GPU pipeline. The <code>RenderContext</code> <em>is</em>
              the <code>Factory</code>. Wired by <code>gl_backend.cpp</code>; flushed per frame.</p>
            <div class="chips"><span class="chip">not cg_renderer — Rive's Apple CoreGraphics path, unused here (CMake include only, 0 source refs)</span></div>

              stencil-then-cover, analytic erf feather, in-shader gradients).</p>
            <div class="chips"><span class="chip">backend/src/render/ · gl_shape_renderer · gl_stencil_renderer · simple_shape_factory</span></div>

        implementations. The same <code>.riv</code> is imported twice — once with each factory —
        so the app can render it through either pipeline and compare them live.</p>

  <!-- 02 -->
  <section>
    <h2><span class="num">02</span>The seven interfaces — how we did each</h2>
    <p class="sub">Every interface below lives in <code>backend/src/render/</code>. Each card states
      the <b style="color:var(--amber)">Contract</b> — what the runtime requires you to fill in — and
      <b style="color:var(--violet)">Ours</b> — how we satisfied it. The recurring idea: keep
      geometry and paint as plain CPU data at build time, then do all GPU work lazily at
      <em>draw</em> time. We reimplement <em>rendering</em> only — never parsing, the Core model,
      or animation.</p>

    <!-- Factory -->
    <div class="iface">
      <div class="top">
        <h3><span class="api">rive::Factory</span><span class="arrow">→</span><span class="impl">SimpleShapeFactory</span></h3>
        <span class="loc">render/simple_shape_factory.hpp:350 · rive/factory.hpp</span>
      </div>
      <p class="contract"><b>Contract</b> Hand back a ref-counted (<code>rcp</code>) render
        resource for each <code>make*</code> the runtime issues while building a scene — a path,
        an empty path, a paint, a linear/radial gradient shader, or a vertex/index buffer — and
        decode in-band image bytes to a <code>RenderImage</code>. The runtime owns lifetimes
        through the <code>rcp</code>; you choose the concrete representation. <code>decodeImage</code>
        may return null on failure.</p>
      <p class="how"><b class="lbl">Ours</b> The object factory the runtime calls <em>during</em> <code>File::import</code>
        to materialise every render resource for the "ours" route. Each <code>make*</code> wraps the
        matching <code>SimpleRender*</code> in an <code>rcp</code> via <code>make_rcp</code>, keeping
        gradients as CPU stop data rather than baking them. <code>decodeImage</code> runs Rive's own
        bundled <code>Bitmap</code> decoder, forces premultiplied RGBA8 (so <code>GL_LINEAR</code> is
        correct at transparent edges), then uploads straight to a GL texture — a GL context is
        already current during import.</p>
      <div class="methods">
        <span class="m">makeRenderPath(RawPath&amp;, FillRule)</span><span class="m">makeEmptyRenderPath()</span>
        <span class="m">makeRenderPaint()</span><span class="m">makeLinearGradient(...)</span>
        <span class="m">makeRadialGradient(...)</span><span class="m">makeRenderBuffer(type, flags, size)</span>
        <span class="m">decodeImage(Span&lt;const uint8_t&gt;)</span>
      </div>
      <p class="cap">SimpleShapeFactory::decodeImage — reuse Rive's decoder, then upload to GL</p>
      <pre class="code">rive::rcp&lt;rive::RenderImage&gt; decodeImage(rive::Span&lt;const uint8_t&gt; span) override
{
    // Decode PNG/JPEG/WebP with Rive's bundled Bitmap decoder, force PREMULTIPLIED
    // RGBA8 (like the official runtime), then wrap a GL texture in SimpleRenderImage.
    auto bmp = Bitmap::decode(span.data(), span.size());
    if (!bmp) return nullptr;
    if (bmp-&gt;pixelFormat() != Bitmap::PixelFormat::RGBAPremul)
        bmp-&gt;pixelFormat(Bitmap::PixelFormat::RGBAPremul);
    return rive::make_rcp&lt;SimpleRenderImage&gt;(bmp-&gt;bytes(), bmp-&gt;width(), bmp-&gt;height());
}</pre>
    </div>

    <!-- Renderer -->
    <div class="iface">
      <div class="top">
        <h3><span class="api">rive::Renderer</span><span class="arrow">→</span><span class="impl">GlStencilShapeRenderer</span></h3>
        <span class="loc">render/gl_stencil_renderer.hpp:26 · rive/renderer.hpp</span>
      </div>
      <p class="contract"><b>Contract</b> Maintain a transform / clip / opacity state stack
        (<code>save</code> / <code>restore</code> / <code>transform</code> /
        <code>modulateOpacity</code>) and execute the draw commands the runtime issues against it —
        <code>drawPath(path, paint)</code>, <code>clipPath(path)</code>, <code>drawImage</code>,
        <code>drawImageMesh</code> — producing pixels however you like. The runtime hands you its
        own <code>RenderPath</code>/<code>RenderPaint</code> pointers; you downcast to read them.</p>
      <p class="how"><b class="lbl">Ours</b> The draw-command sink the runtime issues into. It owns a transform / opacity /
        clip <em>State</em> stack (<code>save</code>/<code>restore</code>/<code>transform</code>/
        <code>modulateOpacity</code> push and mutate the back entry). <code>drawPath</code> downcasts
        the path &amp; paint to our concretes, flattens the <code>RawPath</code> into device-space
        contours under the current transform, then dispatches to a <code>GlShapePipeline</code>
        (solid / gradient / feathered fills, tessellated strokes) that does the actual GPU
        stencil-then-cover into an MSAA FBO. <code>clipPath</code> pushes a flattened device-space
        clip layer (non-convex stencil intersection). It also carries side-channel <em>aux</em> modes
        (id / depth / velocity / bounds / contour) that re-purpose the same draws for the NPR
        post-process — something the official renderer can't feed.</p>
      <div class="methods">
        <span class="m">save() / restore()</span><span class="m">transform(Mat2D&amp;)</span>
        <span class="m">modulateOpacity(float)</span><span class="m">drawPath(path, paint)</span>
        <span class="m">clipPath(path)</span><span class="m">drawImage(img, sampler, blend, opacity)</span>
        <span class="m">drawImageMesh(img, verts, uvs, indices, ...)</span>
      </div>
      <p class="cap">The save/restore/transform/opacity State-stack that backs the adapter</p>
      <pre class="code">void save() override    { m_stack.push_back(m_stack.back()); }
void restore() override { if (m_stack.size() &gt; 1) m_stack.pop_back(); }
void transform(const rive::Mat2D&amp; t) override
{
    m_stack.back().transform = m_stack.back().transform * t;
}
void modulateOpacity(float o) override { m_stack.back().opacity *= o; }</pre>
    </div>

    <!-- RenderPath -->
    <div class="iface">
      <div class="top">
        <h3><span class="api">rive::RenderPath</span><span class="arrow">→</span><span class="impl">SimpleRenderPath</span></h3>
        <span class="loc">render/simple_shape_factory.hpp:231 · rive/renderer.hpp</span>
      </div>
      <p class="contract"><b>Contract</b> Accumulate path geometry: the verb stream
        (<code>moveTo</code> / <code>lineTo</code> / <code>cubicTo</code> / <code>close</code>), a
        fill rule, and combiners that append other paths or a raw path under a transform
        (<code>addRenderPath</code>, <code>addRenderPathBackwards</code>, <code>addRawPath</code>);
        <code>rewind</code> clears it. The runtime never asks you to rasterize — only to hold the
        geometry until it issues a <code>drawPath</code>.</p>
      <p class="how"><b class="lbl">Ours</b> Geometry is stored purely on the CPU as a <code>rive::RawPath</code> + a
        <code>FillRule</code> — there is no tessellation at build time. The verb overrides
        (<code>moveTo</code>/<code>lineTo</code>/<code>cubicTo</code>/<code>close</code>) and the
        <code>add*Path</code> combiners forward straight into the held <code>RawPath</code>, baking
        the supplied <code>Mat2D</code> via <code>RawPath::addPath(&amp;transform)</code> and
        downcasting to recover the concrete when merging two paths. The renderer reads
        <code>rawPath()</code>/<code>fillRuleValue()</code> and flattens to device-space polylines
        only at draw time.</p>

        <span class="m">rewind()</span><span class="m">fillRule(FillRule)</span>
        <span class="m">moveTo / lineTo / cubicTo / close</span><span class="m">addRawPath(RawPath&amp;)</span>

      </div>
      <p class="cap">Verb &amp; combiner overrides forwarding into the held RawPath</p>

    <!-- RenderPaint -->
    <div class="iface">
      <div class="top">
        <h3><span class="api">rive::RenderPaint</span><span class="arrow">→</span><span class="impl">SimpleRenderPaint</span></h3>
        <span class="loc">render/simple_shape_factory.hpp:185 · rive/renderer.hpp</span>

      <p class="contract"><b>Contract</b> Capture the paint state the runtime sets: style
        (fill / stroke), color, stroke thickness / join / cap, feather strength, blend mode, and an
        optional gradient <code>shader</code>. <code>invalidateStroke</code> signals stroke geometry
        should be rebuilt. Pure data — the interface never draws.</p>
      <p class="how"><b class="lbl">Ours</b> A plain CPU value-object: every setter stashes its argument into a member
        (style, color, thickness, join, cap, feather, blend mode, optional shader);
        <code>invalidateStroke</code> is a no-op because no stroke geometry is cached here. Accessors
        expose those to the renderer — <code>colorValue()</code> even folds a bound gradient down to a
        representative average so a solid-color path always has something usable, while
        <code>shaderValue()</code> downcasts back to <code>SimpleRenderShader</code> for full gradient

    <!-- RenderShader -->
    <div class="iface">
      <div class="top">
        <h3><span class="api">rive::RenderShader</span><span class="arrow">→</span><span class="impl">SimpleRenderShader</span></h3>
        <span class="loc">render/simple_shape_factory.hpp:51 · rive/renderer.hpp</span>
      </div>
      <p class="contract"><b>Contract</b> Be an opaque gradient handle. The runtime constructs you
        via <code>Factory::makeLinearGradient</code> / <code>makeRadialGradient</code> (endpoints or
        centre + radius, plus parallel color and stop-position arrays) and hands you back through
        <code>RenderPaint::shader</code>. The base declares <em>no</em> virtuals — you decide how to
        store and later sample the gradient.</p>
      <p class="how"><b class="lbl">Ours</b> <code>RenderShader</code> is an opaque marker base in Rive — no virtuals to
        override — so the gradient lives as data: a kind (linear/radial), start/end points, a radius,
        and a sorted, clamped vector of <code>(position, color)</code> stops captured from the
        factory's arrays. The renderer either feeds those stops to the GL gradient program in object
        space (with the device→object inverse, so radial gradients stay elliptical under rotation), or
        — for the CPU/ImGui path — evaluates a screen point against the stops by bracketing and
        <code>colorLerp</code>.</p>
      <div class="methods">
        <span class="m">isRadial() / startPoint() / endPoint()</span><span class="m">radiusValue()</span>
        <span class="m">gradientStops()</span><span class="m">sample(screenPos, Mat2D&amp;)</span>
        <span class="m">representativeColor()</span>
      </div>
      <p class="cap">Gradient kept as stop data, evaluated by bracketing + colorLerp</p>
      <pre class="code">rive::ColorInt sampleAt(float position) const
{
    if (position &lt;= m_stops.front().position) return m_stops.front().color;
    if (position &gt;= m_stops.back().position)  return m_stops.back().color;
    for (size_t i = 1; i &lt; m_stops.size(); ++i)
        if (position &lt;= m_stops[i].position) {
            float t = (position - m_stops[i-1].position) /
                      (m_stops[i].position - m_stops[i-1].position);
            return rive::colorLerp(m_stops[i-1].color, m_stops[i].color, t);
        }
    return m_stops.back().color;
}</pre>
    </div>

    <!-- RenderBuffer -->
    <div class="iface">
      <div class="top">
        <h3><span class="api">rive::RenderBuffer</span><span class="arrow">→</span><span class="impl">SimpleRenderBuffer</span></h3>
        <span class="loc">render/simple_shape_factory.hpp:289 · rive/render_buffer.hpp</span>
      </div>
      <p class="contract"><b>Contract</b> Back a typed buffer (vertex / index, sized in bytes from
        the base ctor) for image meshes. The runtime writes into it through the map protocol:
        <code>onMap</code> returns a writable pointer, <code>onUnmap</code> finalises the write
        (upload to GPU if you need to). You keep the contents readable at draw time.</p>
      <p class="how"><b class="lbl">Ours</b> Vertex / UV / index buffers for image meshes are just a heap
        <code>std::vector&lt;uint8_t&gt;</code> sized to the requested byte count. The runtime fills it
        through the map/unmap protocol — <code>onMap</code> hands back the raw pointer,
        <code>onUnmap</code> is a no-op (no GPU upload), so the bytes simply live in CPU memory. At
        draw time <code>drawImageMesh</code> reads <code>bytes()</code>/<code>byteSize()</code> to
        expand the mesh into device-space triangles.</p>
      <div class="methods">
        <span class="m">onMap()</span><span class="m">onUnmap()</span>
        <span class="m">+ bytes() / byteSize()</span>

    <h2><span class="num">05</span>The <code>.riv</code> binary round-trip</h2>
    <p class="sub">What turns scene data <em>into</em> bytes, and what reads bytes back. Our writer is
      the one subsystem with no official counterpart — and it is validated by feeding its output
      straight back through the official <code>File::import</code>.</p>

    <div class="card">
      <div class="cap" style="font-size:13px;color:var(--ink);font-family:var(--mono)">on-disk layout (all ints LEB128 varuint unless noted)</div>
      <div class="bytes">
        <div class="seg"><b>HEADER</b><span>"RIVE" · major=7 · minor=0 · fileId</span></div>
        <div class="seg"><b>PROPERTY ToC</b><span>varuint keys → 0, then packed 2-bit field-type bitmap (4 keys / uint32)</span></div>
        <div class="seg"><b>OBJECT STREAM</b><span>[ typeKey · (propKey, value)* · 0 ]* until EOF</span></div>

      <p class="note" style="margin-top:12px">Value width comes from the key's ToC field type:
        <b style="color:var(--ink)">uint</b> → varuint · <b style="color:var(--ink)">double</b> →
        f32 little-endian · <b style="color:var(--ink)">color</b> → 4-byte 0xAARRGGBB ·
        <b style="color:var(--ink)">string</b> → varuint length + bytes. Object order: Backboard →
        Artboard → per shape: Shape → Ellipse/Rectangle → Fill(+fillRule) →
        SolidColor/Gradient(+stops) → Feather → optional Stroke. <code>parentId</code> is an
        artboard-local index, not a global one.</p>

    <p class="sub">A feathered fill is a soft, Gaussian-blurred edge. The original convolves coverage
